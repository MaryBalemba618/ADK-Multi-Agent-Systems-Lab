In this lab, I worked on two multi-agent systems using Google ADK: a travel planner and a movie pitch workflow. The travel planner used a hierarchy where the main agent directed the conversation to either a destination brainstormer or an attractions planner. I added a tool to save selected attractions in session state so the agents could retrieve the list later. For the movie workflow, I worked with sequential, loop, and parallel patterns. The researcher collected information, the screenwriter developed the plot, and the critic reviewed it for improvements. The loop had a five-round limit to prevent it from running endlessly. The parallel stage handled casting suggestions and a box office assessment before the file writer combined the results. Troubleshooting took a large part of this lab. The model initially returned `None`, so I corrected the `.env` settings, copied them into both agent folders, and loaded the variables into the terminal. I also addressed an API-key error by configuring cloud authentication. Other errors came from duplicate `instruction` arguments, instructions pasted outside quotation marks, and missing agent definitions. I corrected the code placement, added the missing screenwriter, and addressed the undefined `exit_loop` reference. When the browser returned `403 Forbidden`, I updated the server command to allow the Cloud Shell origin and matched the Web Preview port to the server port. The blank greeter response taught me to inspect terminal errors instead of repeatedly sending messages. I learned that a syntax check can pass while missing names still prevent the workflow from loading, so testing the module import was useful. I also worked through saving the project as a ZIP backup and preparing it for GitHub with a README, dependency list, and `.gitignore` to keep environment files and credentials private. This lab showed me that building agent systems requires clear responsibilities, correct state handling, and careful testing. In my cloud security work, I can apply these lessons by limiting tool access, checking information passed between agents, reviewing generated claims, and setting execution limits before trusting a system’s output.
